# 흐름 실행 규칙

`/koy-dev:feature`, `/koy-dev:build`, `/koy-dev:bugfix`가 공통으로 따르는 규칙. 각 흐름 SKILL.md는 단계 목록과 그 흐름만의 판단만 적고, 실행 방법은 이 파일을 따른다.

경로 표기: 이 skill의 기준 폴더(Base directory)에서 세 단계 위가 koy-dev plugin 루트(`<koy>`)다.

## 0. 준비

1. `<koy>/reference/koy-config-usage.md`를 읽는다.
2. `.claude/koy-config.md`를 읽는다. 없으면 `/koy-dev:sync`를 먼저 실행하라고 안내하고 멈춘다.
3. **최신인지 확인한다.** 저장소 지문과 koy 버전을 계산해 「sync 기준」과 비교한다.
   - 같으면 그대로 진행한다.
   - 다르면 무엇이 달라졌는지 한 줄로 알리고 묻는다: **지금 sync** / **그대로 진행**. 지금 sync를 고르면 `<koy>/skills/setup/sync/SKILL.md`를 읽고 따른 뒤 돌아온다.
4. **이어하기인지 확인한다.** 인자가 기존 slug이고 `<산출물 위치>/<slug>/flow-state.md`가 있으면, 완료되지 않은 첫 단계부터 이어간다.

## 1. 실행 계획 보고

단계마다 무엇으로 실행하는지 보여주고 **기다리지 않고** 진행한다. 사용자가 중간에 바꾸라고 하면 바꾼다.

```
실행 계획: <흐름 이름> / slug: <slug>
1. grill      koy
2. resting    저장소 skill /development:resting (겹침 결정: 저장소 우선)
3. implement  koy + /figma-to-ui
4. ready      koy
```

`<산출물 위치>/<slug>/flow-state.md`를 만든다.

```markdown
# 흐름 상태: <흐름 이름> / <slug>

| 단계 | 실행 | 상태 | 시작 | 끝 | 결과물 |
| --- | --- | --- | --- | --- | --- |
| grill | koy | 대기 | | | |

## ready 기록
| 시각 | 결과 | 막은 항목 |
| --- | --- | --- |
```

시각은 `date '+%Y-%m-%d %H:%M'`으로 얻는다.

## 2. 단계 실행

단계마다:

1. 「겹침 결정」이 **저장소 우선**이면 그 저장소 skill을 실행한다 (Skill tool 또는 파일 읽기). 결과물은 「저장소 skill의 결과물 위치」에서 찾는다.
2. 아니면 `<koy>/skills/steps/<단계>/SKILL.md`를 읽고 그대로 따른다. 「단계별 연결 skill」도 그 단계 안에서 함께 쓴다.
3. 앞 단계의 결과물 경로를 다음 단계의 입력으로 넘긴다.
4. 단계를 시작할 때 「시작」을, 끝나면 「끝」과 상태 "완료", 결과물 경로를 채운다.

저장소 skill이 자기 단계가 끝나면 멈추라고 하면(같은 턴에 다음 작업을 하지 말라는 규칙 등) **그 지시를 따른다.** flow-state.md를 갱신하고 `/koy-dev:<흐름> <slug>`로 이어서 진행하라고 안내한 뒤 멈춘다.

**확인 지점은 단계 skill 안에 있는 두 곳뿐이다.** grill 마지막의 "이해가 맞나요?"와 implement의 변경 계획 승인. 그 밖의 단계 경계에서는 결과를 짧게 보고하고 바로 다음 단계로 간다. 단계 결과에 사용자 판단이 필요한 문제(막는 실패, 명세와의 큰 차이)가 있을 때만 멈추고 묻는다.

## 3. 대화 길이

단계 경계에서 대화가 길어졌다고 판단되면, 다음 단계로 가기 전에 멈추고 안내한다.

```
/compact <흐름 이름> <slug> 진행 중. 결과물은 <산출물 위치>/<slug>/. 다음 단계: <단계>
그 뒤 /koy-dev:<흐름> <slug> 로 이어서 진행
```

flow-state.md와 결과물 파일이 있으므로 이어서 진행할 수 있다.

## 4. 종료

flow-state.md를 최종 상태로 갱신하고, 결과물 목록과 다음에 할 일을 보고한다. 커밋은 하지 않는다. 작업이 꼬였거나 사용자가 여러 번 방향을 바로잡았으면 `/koy-dev:retro <slug>`를 권한다.
