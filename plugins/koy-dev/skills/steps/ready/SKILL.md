# ready

커밋 전 검증 전용 step. 고치지 않고, stage·commit·push 하지 않는다. 사용자가 고친 뒤 다시 부른다.

검증은 **두 축**이다. 규칙 축은 "규칙을 지켰나", 기준 문서 축은 "요구한 걸 만들었나"를 본다. 규칙을 전부 지키고도 엉뚱한 것을 만들 수 있기 때문에 두 축을 따로 판정하고, 보고에서도 섞지 않는다.

**끝까지 돈다.** 하나가 실패해도 나머지 검사를 계속하고, 실패를 한 번에 모아 보고한다. 앞 검사 실패 때문에 실행 자체가 불가능한 검사만 "미수행 (이유)"로 적는다.

## 원칙

`${CLAUDE_PLUGIN_ROOT}/skills/RULES.md`를 읽고 따른다. 같은 대화에서 이미 읽었으면 건너뛴다.

## 실행

### 1. 변경 범위

`git status`와 `git diff`(stage된 것 포함)로 바뀐 파일과 내용을 정리한다. implement 기록의 「기준 상태」에 적힌 남의 파일은 범위에서 뺀다.

### 2. 규칙 축

1. **검증 명령어**: implement 기록에 적힌 검증 명령어를, 없으면 저장소에서 찾은 검증 명령어를 전부 돌린다. 「기준 상태」와 비교해서 **새로 생긴 실패**만 이번 변경의 실패로 본다. 기존 실패는 이름만 적는다.
2. **프로젝트 규칙**: CLAUDE.md의 규칙을 이번 diff에 맞대어 본다. 위반마다 `파일:줄`과 규칙을 적는다.
3. **실제 동작 확인**: implement 기록의 「실제 동작 확인」에 관찰 기록이 있는지 본다. 없으면 저장소에서 찾은 확인 방법으로 직접 확인한다. 직접 확인할 수 없으면 경고로 올린다.
4. **검증 방법 준수**: 기준 문서에 합의된 테스트 지점이 있으면, 그 지점의 테스트가 이번 변경에 들어 있는지 본다.

### 3. 기준 문서 축

1. 기준 문서를 찾는다. 이 세션의 scratch 폴더(또는 인자로 받은 경로)에서 이 순서로 찾는다: 인자로 받은 issue 파일 → resting.tmp.md → grill.tmp.md → diagnose.tmp.md(버그 수정). 못 찾으면 "기준 문서 없음, 대조 안 함"으로 적고 넘어간다. 기준 문서를 추측해서 만들지 않는다.
2. 대조는 **새 컨텍스트로 시작하는 subagent**에 맡긴다. 기준 문서 경로와 diff만 넘기고, 2단계의 결과나 "통과했다"는 판단은 넘기지 않는다. subagent에게 이렇게 지시한다.
   - 기준 문서의 요구사항과 완료 기준을 하나씩 diff와 맞대어 **빠진 것 / 범위를 넘은 것 / 다르게 만든 것**으로 분류한다.
   - 항목마다 근거(`파일:줄` 또는 기준 문서의 해당 문장)를 붙인다.
3. subagent의 결과는 고치거나 요약하지 않고 그대로 싣는다.

### 4. 판정

| 결과 | 판정 |
| --- | --- |
| 검증 명령어의 새 실패, 프로젝트 규칙 위반 | ❌ 커밋 막음 |
| 실제 동작 확인 없음, 합의된 테스트 누락 | ⚠️ 경고 |
| 기준 문서 축의 차이 | ⚠️ 경고. 기준 문서에서 벗어난 게 옳은 판단일 수 있고, 그 결정은 사용자 몫이다 |
| 기준 문서 축의 **빠진 것** | ⚠️ 경고, 단 종합에 **따로 한 줄**로 올린다. "검증 통과"가 "다 만들었다"로 읽히지 않게 한다 |

### 5. 보고

결과를 화면에 보여주고 기록(`<scratch 폴더>/ready.tmp.md`, issue 파일 기준이면 `ready-<NN>.tmp.md`)로 저장한다. 다시 실행하면 덮어쓴다. scratch 폴더가 없으면 화면에만 보여준다.

### 물어본 것
<RULES.md `tmp.md 기록 규칙`의 `물어본 것` 형식. 없으면 "없음">
