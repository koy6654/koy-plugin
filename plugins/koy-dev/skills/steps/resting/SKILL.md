# resting

시작할 때 이 skill의 기준 폴더에서 세 단계 위(koy-dev plugin 루트)의 `reference/koy-config-usage.md`를 읽고 따른다.

grill 다음의 검증 단계. 정한 요구사항을 실제 코드와 대조 대상에 맞대어 **빈틈**과 **놓친 점**을 찾고, implement가 따라갈 **명세서**를 만든다. 분석만 한다. 쓰기는 「산출물 위치」 안에서만 한다.

## 근거 원칙

기억, 대화 내용, 과거 ADR, grill에서 본 내용은 전부 **힌트**다. 사실로 쓰려면 지금의 코드나 원천을 직접 확인한다. 모든 주장은 출처와 함께 쓴다.

```
<확인된 사실>. 출처: <파일:심볼 | 문서 위치 | 실행한 명령과 결과>
```

출처를 붙일 수 없는 주장은 「남은 불확실성」에 둔다.

## 1. 불러오기

1. `.claude/koy-config.md`를 읽는다. 파일이 없으면 멈추고 `/koy-dev:sync`를 먼저 실행하라고 안내한다.
2. 인자로 받은 requirements.md를 읽는다. 관련 ADR과 용어집이 있으면 함께 읽는다.

## 2. 열린 질문 해소

requirements.md의 「열린 질문」을 하나씩 처리한다.

```markdown
### 열린 질문: <질문>
- 결론:
- 확인 방법:
- 출처:
- 남은 불확실성:
```

**완료 기준**: 모든 열린 질문에 결론이나 「남은 불확실성」이 적혀 있다.

## 3. 대조

「대조 대상」의 항목마다 요구사항과 맞대어 본다. 어긋나는 점, 요구사항에 없는데 원천에 있는 것, 원천에 없는데 요구사항에 있는 것을 적는다. "없음"인 항목은 건너뛰고 건너뛴 사실을 남긴다.

**완료 기준**: 「대조 대상」의 모든 항목에 결과 또는 "건너뜀 (없음)"이 적혀 있다.

## 4. 비슷한 기능과 비교

"기존 기능 X와 같겠지"는 가설이다. 가장 비슷한 기존 기능을 찾아 새 요구사항과 나란히 놓고 비교한다: 무엇이 시작시키나, 상태가 어떻게 바뀌나, 권한, 에러 처리, 데이터 형태, 완료 후 무엇이 남나.

차이를 영향도로 나눈다.

```markdown
## 빈틈
### High
### Medium
### Low
```

## 5. 놓친 점

「놓친 점 체크리스트」의 **모든 항목**에 답한다. 해당 없음도 이유와 함께 적는다. 체크리스트 밖에서 구현에 영향을 줄 것을 찾았다면 추가로 적는다.

## 6. 검증 방법 합의

implement가 결과를 어떻게 증명할지 정한다.

- 테스트가 있는 프로젝트: 동작을 밖에서 관찰할 수 있는 지점 중 **가장 높은 곳 하나**를 테스트 지점으로 고른다. 이미 테스트가 걸린 지점이 있으면 그것을 쓴다. 같은 지점의 기존 테스트 파일을 참고 예시로 적는다.
- 테스트가 없거나 마땅한 지점이 없는 경우: 「실제 동작 확인」에 따라 **관찰할 시나리오**를 적는다 (무엇을 하고, 무엇이 보여야 통과인가). 마땅한 테스트 지점이 없다는 사실도 빈틈에 올린다.

정한 검증 방법은 명세에 적고 보고에 포함한다. 사용자는 implement의 변경 계획 승인에서 이를 다시 본다.

## 7. 남은 결정

코드와 원천으로 정할 수 없는 제품·비즈니스 판단이 남았으면 grill과 같은 라운드 형식으로 묻는다. 코드로 답이 나오는 것은 코드로 답한다.

## 8. 명세서

`<산출물 위치>/<slug>/spec.md`를 쓴다. 파일 경로와 코드 조각은 넣지 않는다. 금방 낡는다.

```markdown
# <기능 이름> 구현 명세

## 1. 요약
## 2. 확인된 맥락
<근거 원칙 형식의 사실 목록>
## 3. 열린 질문 결과
## 4. 대조 결과
## 5. 빈틈
## 6. 놓친 점
## 7. 구현 결정
<바꿀 모듈과 그 인터페이스, 데이터 형태, 상태 모델>
## 8. 검증 방법
<합의된 테스트 지점 또는 관찰 시나리오>
## 9. 범위 밖
## 10. 회귀 위험
## 11. 남은 불확실성
```

## 9. 종료

흐름 skill(`/koy-dev:feature`, `/koy-dev:build`, `/koy-dev:bugfix`) 안에서 실행 중이면, 결과를 보고하고 흐름 skill의 다음 지시로 돌아간다. 아래 안내는 이 skill을 단독으로 실행했을 때만 따른다.

명세서 경로와 주요 발견을 보고하고 멈춘다. 다음 단계를 안내한다.

- 한 세션에 끝나지 않을 작업: `/koy-dev:split <spec.md 경로>`
- 그 외: `/koy-dev:implement <spec.md 경로>`
