# debug

원인 찾기 전용 step. 이 step이 끝나면 **왜 틀리는지**가 정해져 있다. 코드는 고치지 않는다.

명령과 출력을 보여줄 때는 비밀값을 `<REDACTED>`로 가린다.

## 원칙

- `${CLAUDE_PLUGIN_ROOT}/skills/RULES.md`를 읽고 따른다. 같은 대화에서 이미 읽었으면 건너뛴다.

## 실행

### 1. 확인 루프 만들기

이 step이 전부다. 이 버그에서 **빨갛게** 실패하는 확인 수단이 있으면 원인은 찾게 된다. 없으면 코드를 아무리 읽어도 소용없다. 여기에 가장 많은 노력을 쓴다.

만드는 방법, 대략 이 순서로:

1. 버그에 닿는 지점의 실패하는 테스트
2. 실행 중인 개발 서버에 보내는 HTTP 요청 스크립트
3. 고정 입력으로 실행하고 출력을 기준 결과와 비교하는 CLI 실행
4. 화면을 조작하고 DOM·콘솔·네트워크를 확인하는 헤드리스 브라우저 스크립트
5. 실제로 캡처한 요청이나 로그를 그 코드 경로에 다시 흘려보내기
6. 버그 경로만 띄우는 임시 실행 환경
7. 두 버전(또는 두 설정)에 같은 입력을 넣고 결과 비교
8. 최후 수단: 사람이 직접 조작하고 결과를 알려주는 절차

루프를 만든 뒤에는 **좁힌다**: 더 빠르게, 증상을 더 정확히 단언하게, 매번 같은 결과가 나오게. 가끔만 나는 버그는 깔끔한 재현이 아니라 **재현율을 높이는 것**이 목표다.

**완료 기준**: 다음을 만족하는 **명령 하나**를 이미 한 번 이상 실행했고, 그 명령과 출력을 보여줬다.

- [ ] 실제 버그 경로를 지나고 **사용자가 말한 증상**을 단언한다. 고치면 초록이 된다
- [ ] 매번 같은 판정을 낸다 (가끔 나는 버그는 높은 재현율로 고정)
- [ ] 몇 초 안에 끝난다
- [ ] 에이전트가 혼자 돌릴 수 있다

루프를 만들 수 없으면 멈추고 그렇게 말한다. 시도한 것을 나열하고, 재현 환경 접근이나 캡처한 로그·화면 녹화를 사용자에게 요청한다. 루프 없이 가설로 넘어가지 않는다.

### 2. 재현과 축소

루프를 돌려 빨갛게 되는 것을 본다. **사용자가 말한 그 증상**인지 확인한다. 근처의 다른 실패면 엉뚱한 버그다.

빨갛게 된 뒤에는 입력, 호출부, 설정, 데이터, 절차를 **하나씩** 빼면서 매번 루프를 다시 돌린다. 하나라도 더 빼면 초록이 되는 지점에서 멈춘다. 남은 것은 전부 원인에 필요한 요소다.

### 3. 가설

검증하기 전에 **가설을 3~5개** 세우고 순위를 매긴다. 가설마다 예측을 적는다.

> "<X>가 원인이면, <Y>를 바꾸면 버그가 사라진다 / <Z>를 바꾸면 더 심해진다."

예측을 적을 수 없는 가설은 버리거나 다듬는다. 순위 목록을 사용자에게 보여준다. 사용자가 순위를 바로잡을 수 있다. 응답을 기다리지 않고 순위대로 진행해도 된다.

### 4. 계측

계측 하나는 가설 하나의 예측에 대응한다. **한 번에 변수 하나만** 바꾼다. 디버거가 있으면 디버거를, 없으면 가설을 가르는 경계에만 로그를 단다. 모든 디버그 로그에는 `[DEBUG-<4자리>]` 같은 고유 접두어를 붙인다.

성능 문제는 로그 대신 기준 측정값을 먼저 잡고, 같은 방법으로 다시 측정하며 좁힌다.

### 5. 수정과 회귀 테스트

맞는 테스트 지점이 있으면 **수정 전에** 회귀 테스트를 쓴다. 맞는 지점은 호출부에서 실제로 일어나는 형태 그대로 버그를 재현하는 자리다. 그런 자리가 없으면 그 사실 자체를 발견으로 적는다.

1. 축소한 재현을 그 지점의 실패하는 테스트로 만든다
2. 실패하는 것을 본다
3. 원인을 고친다. 증상이 아니라 원인을 고치고, 같은 원인을 지나는 다른 호출부도 함께 확인한다
4. 통과하는 것을 본다
5. 1단계의 원래 루프를 축소 전 시나리오로 다시 돌린다

### 6. 정리

- [ ] 원래 재현이 더 이상 재현되지 않는다
- [ ] 회귀 테스트가 통과한다 (또는 테스트 지점이 없다는 사실이 적혀 있다)
- [ ] `[DEBUG-` 접두어로 찾아서 계측을 전부 지웠다
- [ ] 임시 실행 환경을 지웠다
- [ ] 맞았던 가설을 debug.tmp.md에 적었다. 커밋 메시지에 그대로 쓸 수 있게 한다

기록 `<scratch 폴더>/debug.tmp.md`를 쓴다: 재현 명령과 출력, 축소한 재현, 가설 목록과 맞았던 가설, 원인, 수정 내용, 회귀 테스트(또는 테스트 지점이 없다는 사실), 맨 끝에 `물어본 것`(RULES.md `tmp.md 기록 규칙`의 `물어본 것` 형식).
