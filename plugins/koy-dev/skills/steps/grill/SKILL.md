# grill

시작할 때 이 skill의 기준 폴더에서 세 단계 위(koy-dev plugin 루트)의 `reference/koy-config-usage.md`를 읽고 따른다.

요구사항 정리 전용 단계. 이 단계가 끝나면 **무엇을 만들지**가 정해져 있다.

| 이 단계에서 하지 않는 것 | 맡는 곳 |
| --- | --- |
| 코드·명세와의 깊은 대조, 빈틈 분석 | `/koy-dev:resting` |
| 작업 나누기 | `/koy-dev:split` |
| 코드 수정 | `/koy-dev:implement` |

## 0. 준비

1. `.claude/koy-config.md`를 읽는다. 「이미 정해진 것」은 질문하지 않고 전제로 쓴다. 파일이 없으면 그 사실을 한 줄로 알리고 진행한다.
2. 요청과 관련된 코드·문서를 **가볍게** 훑는다. 목적은 질문의 질을 높이는 것이다.
   - 코드로 확인된 사실은 사용자에게 묻지 않고 질문의 전제로 쓴다.
   - 가볍게 본 것만으로 단정할 수 없는 사실은 **열린 질문**으로 적어 resting에 넘긴다.
   - 사실 확인이 길어지면 새 컨텍스트로 시작하는 subagent에 맡긴다. 그 확인에 매달린 질문만 기다리고, 나머지는 지금 묻는다.

## 1. 결정 트리와 라운드

요청을 **결정 트리**로 그린다. 결정 하나는 거기 매달린 결정들로 가지를 친다.

**frontier**는 선행 결정이 모두 정해져서 **지금** 물을 수 있는 질문 전부다. 라운드마다 frontier 전체를 한 번에 묻고, 답을 받은 뒤 frontier를 다시 계산한다. 아직 답을 듣지 못한 질문에 매달린 질문은 다음 라운드로 미룬다.

같은 라운드 안에서는 이 순서로 번호를 매긴다.

1. 목표
2. 범위와 제외 범위
3. 제약
4. 완료 기준
5. 기존 맥락과 영향 범위

라운드 형식:

```
❓ **Q1 - <질문 제목>**: <질문 본문. 선택지가 있으면 함께>

➡️ <추천 답>

---

❓ **Q2 - <질문 제목>**: ...
```

"네"라고 답하면 추천 답을 받아들이는 것이 되도록 질문을 쓴다. 결정은 사용자 몫이다. 라운드마다 답을 기다린다.

**완료 기준**: frontier가 비었다. 트리의 모든 가지를 돌았고, 조용히 가정한 것이 남아 있지 않다. 이때 아래가 전부 채워져 있다.

- [ ] 목표가 한 문장으로 쓰여 있다
- [ ] 포함 범위와 제외 범위가 나뉘어 있다
- [ ] 기술·일정·비즈니스 제약이 정리되어 있다
- [ ] 완료 기준이 확인 가능한 문장으로 쓰여 있다
- [ ] 기존 맥락과 영향 범위가 0단계에서 본 사실을 근거로 정리되어 있다
- [ ] 깊은 확인이 필요한 항목이 열린 질문으로 남아 있다

사용자가 "충분하다"고 하면 그 시점에서 3단계로 간다. 위 체크리스트 중 비어 있는 항목은 문서에 "미정"으로 남긴다.

## 2. 용어와 결정

- 용어가 확정되면 「산출물 위치」의 용어집에 바로 적는다. 용어집이 "없음"이면 건너뛴다.
- ADR은 세 조건이 **모두** 맞을 때만 제안한다. 되돌리기 비싸다, 맥락 없이 보면 의아하다, 실제 대안을 비교해서 골랐다.

## 3. 요구사항 문서

사용자가 이해가 맞다고 확인하면 `<산출물 위치>/<slug>/requirements.md`를 쓴다. slug는 기능을 나타내는 짧은 영문 kebab-case로 정하고 사용자에게 보여준다.

```markdown
# <기능 이름> 요구사항

## 목표
## 범위
### 포함
### 제외
## 제약
## 완료 기준
## 기존 맥락과 영향 범위
## 결정 기록
<라운드에서 정한 결정과 이유>
## 열린 질문 (resting에서 확인)
```

## 4. 종료

흐름 skill(`/koy-dev:feature`, `/koy-dev:build`, `/koy-dev:bugfix`) 안에서 실행 중이면, 결과를 보고하고 흐름 skill의 다음 지시로 돌아간다. 아래 안내는 이 skill을 단독으로 실행했을 때만 따른다.

산출 문서 경로와 결정 요약을 보고하고 멈춘다. 다음 단계를 안내한다.

- 큰 기능이나 위험한 변경: `/koy-dev:resting <requirements.md 경로>`
- 그 외: `/koy-dev:implement <requirements.md 경로>`
