# verify

검증 전용 step. 이 step이 끝나면 **커밋해도 되는지**가 정해져 있다. 코드는 고치지 않고, 커밋하지 않는다.

## 원칙

- `${CLAUDE_PLUGIN_ROOT}/skills/RULES.md`를 읽고 따른다. 같은 대화에서 이미 읽었으면 건너뛴다.
- **실패해도 끝까지 검사한다.** 실패는 모아서 한 번에 보고한다. 앞 실패 때문에 실행할 수 없는 검사는 미수행으로 적고 이유를 붙인다.

## 실행

### 1. 변경된 범위 읽기

`git status`와 `git diff HEAD`로 마지막 커밋 이후 바뀐 파일과 내용을 정리한다.

### 2. 규칙

1. **검증 명령어**
   - ticket 파일의 `기준 상태`에 적힌 검증 명령어를 전부 돌린다. 적힌 것이 없으면 저장소에서 찾은 검증 명령어를 돌린다.
   - 결과를 ticket 파일의 `기준 상태`와 비교한다. 원래부터 있던 실패는 "기존"으로 이름만 적고, **새로 생긴 실패**만 이번 변경의 실패로 본다.
2. **프로젝트 규칙**: CLAUDE.md의 규칙을 이번 diff에 맞대어 본다. 위반마다 `파일:줄`과 규칙을 적는다.
3. **실제 동작 확인**
   - ticket 파일의 `기준 상태`에 적힌 실제 동작 확인 방법과 ticket 파일의 변경 계획에 적힌 검증 방법대로, 만든 것을 직접 실행해 확인한다. 무엇을 했고 무엇을 봤는지 모아 둔다.
   - 빌드 통과와 자기 판단은 증거로 치지 않는다.
   - 확인 과정을 스크립트로 만들 수 있으면 scratch 폴더에 만들어 돌린다.
   - 직접 확인할 수 없으면 이유와 사용자가 확인할 방법을 모아 둔다. "확인 못 함"은 통과가 아니다.
4. **검증 방법 준수**: spec.tmp.md의 `검증 방법`에 합의된 테스트 지점이 있으면, 그 지점의 테스트가 이번 변경에 들어 있는지 본다.

### 3. 요구사항과 설계

1. 아래 문서를 우선순위에 맞게 모두 읽는다. 내용이 서로 다르면 우선순위가 위에 있는 것을 따른다. 하나도 없으면 "요구사항과 설계 문서 없음, 대조 안 함"으로 적고 넘어간다. 문서를 추측해서 만들지 않는다.
   - 입력으로 주어진 ticket 파일
   - scratch 폴더의 spec.tmp.md
   - scratch 폴더의 scope.tmp.md
   - scratch 폴더의 debug.tmp.md
2. 대조는 **새 컨텍스트로 시작하는 subagent**에 맡긴다. 읽은 문서 경로와 diff만 넘기고, 2단계의 결과나 "통과했다"는 판단은 넘기지 않는다. subagent에게 이렇게 지시한다.
   - 문서의 요구사항, 완료 기준, 설계를 하나씩 diff와 맞대어 **빠진 것 / 범위를 넘은 것 / 다르게 만든 것**으로 분류한다.
   - 항목마다 근거(`파일:줄` 또는 문서의 해당 문장)를 붙인다.
3. subagent의 결과는 고치거나 요약하지 않고 그대로 싣는다.

### 4. 판정

| 결과                                      | 판정                                                                                       |
| ----------------------------------------- | ------------------------------------------------------------------------------------------ |
| 검증 명령어의 새 실패, 프로젝트 규칙 위반 | ❌ 커밋 막음                                                                               |
| 실제 동작 확인 없음, 합의된 테스트 누락   | ⚠️ 경고                                                                                    |
| 요구사항과 설계의 차이                    | ⚠️ 경고. 요구사항이나 설계에서 벗어난 게 옳은 판단일 수 있고, 그 결정은 사용자 몫이다      |
| 요구사항과 설계의 **빠진 것**             | ⚠️ 경고, 단 종합에 **따로 한 줄**로 올린다. "검증 통과"가 "다 만들었다"로 읽히지 않게 한다 |

### 5. 보고

결과를 화면에 보여주고 기록으로 저장한다. scratch 폴더가 없으면 화면에만 보여준다.

```markdown
### 요구사항과 설계

<통과했을 때만. 저장소의 커밋 규칙(CLAUDE.md, 최근 커밋 메시지)을 따른다>

### 물어본 것

<RULES.md `tmp.md 기록 규칙`의 `물어본 것` 형식. 없으면 "없음">
```
