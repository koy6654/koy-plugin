# debug

버그 원인 분석 전용 step. 이 step이 끝나면 **버그가 왜 생기는지**가 정해져 있다. 코드는 고치지 않는다.

## 원칙

- `${CLAUDE_PLUGIN_ROOT}/skills/RULES.md`를 읽고 따른다. 같은 대화에서 이미 읽었으면 건너뛴다.

## 실행

### 1. 입력 읽기

입력으로 받은 증상, 재현 방법, 기대한 동작을 읽는다. 증상이나 기대한 동작이 없으면 묻는다.

### 2. 확인 루프 만들기

버그가 있으면 실패하고, 고치면 통과하는 확인 루프를 먼저 만든다. 원인은 이 확인 루프로 찾는다.
코드만 읽어서는 짐작밖에 할 수 없다. 시간이 걸려도 이 단계는 건너뛰지 않는다.

확인 루프는 아래 방법 중 위에 있는 것부터 시도해, 처음 되는 것을 쓴다.

1. 버그가 나는 코드를 직접 실행해서 실패하는 테스트
2. 실행 중인 서버에 직접 요청을 보내는 스크립트
3. 버그를 일으키는 입력 데이터를 파일로 고정해 그 코드를 실행하고, 실행 결과를 기대한 결과와 비교하는 스크립트
4. 브라우저에서 화면을 조작하고 DOM, 콘솔, 네트워크를 확인하는 스크립트
5. 실제로 들어온 요청이나 로그를 그 코드에 다시 넣어 돌리는 스크립트
6. 버그가 나는 부분만 따로 띄운 임시 실행 환경
7. 두 버전이나 두 설정에 같은 입력을 넣어 결과를 비교하는 스크립트
8. `최후 수단`으로 사용자가 직접 해 보고 결과를 알려 주는 절차 진행

### 3. 확인 루프 실행하기

위에서 만든 확인 루프를 실제로 실행하고, 그 명령과 출력을 보여준다.

- **입력으로 받은 증상**으로 실패하는지 본다. 근처의 다른 실패면 엉뚱한 버그다.
- 확인 루프가 아래를 모두 만족하는지 본다.
  - 실제 버그 경로를 지나고 입력으로 받은 증상을 단언한다. 고치면 통과한다
  - 매번 같은 판정을 낸다. 가끔만 나는 버그는 재현율을 높여서 고정한다
  - 몇 초 안에 끝난다
  - 에이전트가 혼자 돌릴 수 있다
- 확인 루프를 만들 수 없거나 위를 만족하지 못하면 멈추고 그렇게 말한다. 시도한 것을 나열하고, 재현 환경 접근이나 캡처한 로그·화면 녹화를 사용자에게 요청한다. 확인 루프 없이 가설로 넘어가지 않는다.

### 4. 확인 루프 재현 케이스 확정하기

재현 케이스에서 버그와 상관없는 것을 빼고, 버그를 일으키는 데 꼭 필요한 것만 남긴다.

- 입력, 호출부, 설정, 데이터, 절차를 하나씩 빼고 매번 확인 루프를 다시 돌린다.
- 빼도 여전히 실패하면 뺀 것은 원인과 상관없으므로 뺀 채로 둔다.
- 빼서 통과하면 뺀 것은 원인에 필요하므로 되돌려 남긴다.
- 더 뺄 것이 없으면 멈춘다. 남은 재현 케이스가 다음 단계에서 가설을 세울 범위다.

### 5. 버그 원인 가설 세우기

**가설을 3~5개** 세우고 순위를 매긴다. 가설마다 예측을 적는다.

> "<X>가 원인이면, <Y>를 바꾸면 버그가 사라진다 / <Z>를 바꾸면 더 심해진다."

예측을 적을 수 없는 가설은 버리거나 다듬는다. 순위가 높은 가설부터 다음 단계에서 확인한다.

### 6. 버그 원인 가설 확인하기

순위가 높은 가설부터 하나씩, 예측대로 결과가 나오는지 확인한다. 예측대로 나온 가설을 원인으로 정한다.

- 디버거가 있으면 디버거를 쓰고, 없으면 가설을 가르는 지점에만 로그를 넣는다.
- 한 번에 하나만 바꾼다. 여러 개를 함께 바꾸면 무엇 때문에 결과가 달라졌는지 알 수 없다.
- 로그에는 `[DEBUG-<4자리>]` 같은 고유 표시를 붙인다. `정리` 단계에서 이 표시로 찾아 지운다.
- 성능 문제는 로그 대신 먼저 시간을 재 두고, 같은 방법으로 다시 재며 좁힌다.

### 7. 회귀 테스트 지점 정하기

맞는 테스트 지점을 찾는다. 맞는 지점은 호출부에서 실제로 일어나는 형태 그대로 버그를 재현하는 자리다. 그런 자리가 없으면 그 사실 자체를 발견으로 적는다.

1. 확정한 재현 케이스를 그 지점에서 어떤 입력으로 무엇을 단언하는 테스트로 만들지 정한다
2. 같은 원인을 지나는 다른 호출부를 찾아 적는다

테스트 작성과 수정은 build가 한다.

### 8. 정리

- `버그 원인 가설 확인하기`에서 넣은 `[DEBUG-` 표시의 로그를 모두 지운다.
- `확인 루프 만들기`에서 만든 임시 실행 환경을 지운다.

### 9. 기록 쓰기

`tmp.md 기록 규칙`대로 `<scratch 폴더>/debug.tmp.md`를 쓰고, 아래를 덧붙인다.

- 확인 루프: 실행한 명령과 출력
- 확정한 재현 케이스
- 가설 목록과 맞은 가설. 커밋 메시지에 그대로 쓸 수 있게 적는다
- 원인
- 회귀 테스트 지점과 단언할 증상. 테스트 지점이 없으면 그 사실
- 같은 원인을 지나는 다른 호출부

### 10. 종료

debug.tmp.md 경로와 원인을 간결하고 이해하기 쉽게 보고하고 멈춘다.
